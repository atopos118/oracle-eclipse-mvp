# 《甲骨里的日光缺口》系统架构（MVP 0.4）

## 1. 逻辑架构

```text
公众科普站
  -> 公众API
  -> data/published-snapshot.json（当前发布版本的技术文件）

研究工作台 / 输出工作室 / 审核发布中心
  -> 本机研究API
  -> SQLite可审计证据库
       |- source_documents      原始资料元数据与指纹
       |- source_units          页或文本单元
       |- ocr_runs             OCR任务、模型、进度与质量报告
       |- ocr_page_results     OCR逐页结果与质量分数
       |- knowledge_candidates 历史候选知识兼容表（当前流程不使用）
       |- published_knowledge   进入公众快照的发布知识
       |- artifacts             作品草稿与作品
       |- lineage_edges         来源关系
       |- review_events         审核记录
       |- prompt_versions       提示词版本
       |- publish_snapshots     发布版本记录

百炼适配层
  -> 检索选定资料/已批准知识
  -> 生成草稿或回答
  -> 返回引用
  X 不能写入source_documents/source_units

媒体导出层
  -> 读取作品草稿或已批准作品
  -> 音频导览文稿通过百炼原生Qwen3-TTS接口生成WAV并写入私有缓存
  -> 百炼文生图按卡片生成无文字插图，程序叠加审核文本后生成PNG/ZIP
  -> 百炼生成幻灯片结构，程序渲染翻页阅读和可编辑PPTX
  -> 视频制作包生成脚本/分镜/SRT/清单ZIP
  X 不读取或打包原始PDF

结构化画布层
  -> 白板与思维导图共用nodes/edges/viewport数据模型
  -> 研究台可拖动、连线、编辑属性并绑定资料页
  -> 服务端限制节点数量、坐标、尺寸、类型和引用字段
  -> 公众端只读渲染当前发布版本
  X 节点内容不写回source_documents/source_units
```

## 2. 四类存储

### 证据库

保存原始资料、解析单元、页码、内容指纹和处理状态，只在研究端使用。

### 发布知识库

保存人工审核通过的释文、著录号、年代、观点和争议。它是公众发布版本的唯一知识来源。

### 作品库

保存草稿、审核状态、发布版本和`generation_instruction`。草稿与正式作品使用同一实体，通过状态区分。媒体文件按需从作品JSON生成，不作为证据节点，也不反向进入资料检索。白板与思维导图也保存在作品JSON中，节点引用仅指向既有资料、知识或作品。

### 站点内容库

`site_content_entries`保存任意公众栏目及其`content_key/section_type/nav_label/kicker/title/summary/body_html/enabled/sort_order`，同时保留当前编辑内容与最近发布内容。系统默认栏目以兼容模板提供，首次修改或排序时再物化到数据库。正文HTML经过服务端白名单净化；简码只允许映射到注册的数据渲染器。状态分为审核轴`draft/approved`和发布轴`private/public/outdated`；编辑已发布内容只产生待更新草稿，当前公众版本继续读取上次冻结内容。`site_assets`保存图片和视频的哈希、类型、私有路径与大小，公众媒体接口必须先确认媒体编号被当前发布版本引用。

### 来源关系

使用有向边记录“知识/作品依赖哪个资料单元”，并附模型、系统提示词版本、用户生成要求和运行信息。证据节点不能以模型生成作品作为来源。

问答结果保存为AI研究笔记时，资料实体标记`source_role=generated_note`并记录问题、回答、引用、模型和提示词版本；该实体不能作为证据上游，也不参与检索。

## 3. 关键状态机

### 资料

`imported -> parsed -> reviewed`；失败为`parse_failed`，删除为`deleted`，重解析时版本号递增。

`parsed`表示已经完成解析但只能在资料库中校核；`reviewed`表示来源确认完成，可以进入私有研究、作品生成、作品批准和公众发布。PDF的OCR文本确认会直接写入`reviewed`，不再要求第二次资料复核。资料库对PDF同时提供嵌入原页和页码级原文联动。

PDF另有识别状态：`ocr_pending -> ocr_processing -> ocr_needs_review -> ocr_ready`。旧解析单元保留；OCR全部成功并通过自动质量门后，以新`parse_version`写入。`ocr_pending`、`ocr_processing`和`ocr_failed`不得进入检索。

### 发布知识

历史候选数据仍可被旧快照读取，但当前研究台不再把候选提取和候选审核作为独立工作流。进入公众快照的知识必须有明确来源关系和审核记录；来源变化后为`stale`。

### 作品

`draft -> approved -> published`；来源变化后为`stale`，重审后才能再次发布。

### 发布版本

界面使用“发布版本”，底层仍以不可变快照文件实现。`building -> published | failed`。公众端只读取当前发布版本；每次发布另存独立归档文件。恢复旧版本时生成新的当前版本，不原地覆盖历史。

“快照”是实现手段，不是面向研究人员的主要产品概念。它用于冻结一次发布的知识、作品、来源关系和统计，支持审计、对比、回滚，并隔离审核过程中的中间状态。

发布版本从MVP 0.5结构开始包含`siteContent`，MVP 0.6扩展为有序栏目清单和HTML/简码正文。恢复历史版本时，站点内容与作品一起恢复为新的当前版本；工作区内较新的未发布草稿不被历史版本无痕覆盖，而标记为待更新。

## 4. 失效传播

资料内容指纹或解析版本发生变化时：

1. 找出以该资料或资料单元为上游的来源关系。
2. 将依赖的候选知识、发布知识和作品标记为`stale`。
3. 当前公众发布版本不自动覆盖，审核过程不影响线上稳定内容。
4. 审核人员处理失效项并显式发布新版本。

删除资料使用软删除，保留审计记录和历史关系，但后续快照不得继续选入其依赖项。

## 5. 百炼适配层

统一接口：

- `answer(question, published_snapshot)`：公众问答，只使用当前发布版本的底层快照文件。
- `research_answer(question, selected_sources)`：私有资料问答，只接受已确认资料，返回页码与确认状态。
- `ocr_page(page_image)`：只传输本机渲染的单页PNG，返回逐字转写，不上传原PDF。

作品生成前按来源保留最相关的页码摘录，默认每篇不超过5段、总计不超过32段、每段不超过1200字，以控制模型上下文和响应时间；底层来源关系仍保留全部实际依赖页码。通用百炼请求默认超时为120秒，可由`QWEN_REQUEST_TIMEOUT`在30至300秒范围内配置。作品生成超时后自动使用确定性的本地证据模板，模型字段记录降级原因，草稿仍需正常审核。
- `generate_artifact(kind, selected_sources)`：研究端草稿生成，只使用选定证据单元。
- `generate_site_content(content_key, generation_mode, instruction)`：基于当前站点内容、已发布科学知识和受约束提示生成栏目草稿；`section_package`返回完整栏目字段和配图描述，`html_body`只返回正文HTML。完整栏目配图通过百炼文生图生成后登记为私有站点媒体，媒体编号和操作链接不会由文本模型篡改。
- 旧版本仍兼容`extract_candidates(selected_sources)`，但当前首版界面不触发该接口；模型结果只能保存为AI研究笔记或作品草稿。

所有运行记录`model`、`prompt_version`、`input_ids`、`created_at`和输出哈希。无密钥时由本地确定性模板实现同一接口。

三类媒体模板要求模型只返回结构化JSON：`visual_card_set`返回图卡数组，`slide_deck`返回逐页叙事、版式、富文本、图标、配图计划、智能图形、真实数据图表、讲者备注与播放设置，`video_package`返回带起止时间的分镜数组。`media_exports.py`负责调度导出，`tools/export_presentation.mjs`使用`@oai/artifact-tool`生成可编辑PPTX，随后由标准Office Open XML写入转场、自动换页与循环播放设置。图标限定在项目内置Lucide集合；图表仅接受资料明确支持的数值；流程和证据链使用原生PowerPoint形状；百炼生成图片作为独立作品资源嵌入，不使用不可编辑的整页图片。研究台与公众端共用同一逐页数据与播放规则。生成或替换图片会使作品回到待审核，单纯下载导出不改变审核或发布状态。

`audio_guide`保存可审核朗读文稿，`media_exports.py`调用百炼语音模型生成有效WAV。长文稿按语义边界分段合成后合并，文件按作品、文稿、模型和声音指纹缓存于私有目录。研究接口允许草稿播放与下载；公众接口先检查作品是否存在于当前发布版本，再基于该版本冻结的文稿、语音模型和声音返回音频，不能通过猜测私有草稿编号取得音频。

全部20类作品共用可选`generation_instruction`。适配层把它作为独立、不可信的表达偏好传入模型，系统提示继续强制只使用选定资料，并禁止用户要求改变事实字段、来源关系和审核发布状态。

百炼调用采用最小必要传输：OCR只发送当前单页PNG；公众问答只发送当前发布版本的相关知识；私有资料问答和作品生成只发送用户所选且通过质量门的文本片段。原始PDF、SQLite数据库、未审核候选和无关资料不发送到百炼。研究资料进入第三方推理前仍需确认授权边界。

## 6. 部署边界

- 本地研究模式：默认`127.0.0.1`，开放研究UI和研究API。
- 公众部署模式：禁用研究UI和研究API，只提供公众站、公众API和快照文件。
- 公网比赛演示模式：应用继续绑定`127.0.0.1`，由同机HTTPS反向代理或安全隧道同时公开公众站与登录后的研究工作台；启用Secure Cookie、代理来源识别和接口限流。
- 三种模式共享代码，但不共享静态暴露面；任何模式都不允许通过静态路径读取原始PDF、SQLite、缓存或历史发布文件。

## 7. 主要模块职责

- `research_store.py`：资料、作品、提示词、审核事件、来源关系、站点内容、已发布内容副本和私有站点媒体。
- `bailian_adapter.py`：问答与20类作品的百炼/本地结构化生成。
- `media_exports.py`、`tools/export_presentation.mjs`：百炼语音WAV、图卡PNG、增强可编辑PPTX和视频制作包ZIP的可审计导出。
- `snapshot_manager.py`：冻结并发布公众版本。
- `server.py`：研究API、公众API、媒体导出路由和部署边界。
