# 5—10人用户测试执行包

首轮建议8人，最低有效样本5人、最多10人。这里提供招募席位、任务、观察记录、问卷和
汇总工具；真实参与者完成测试并录入后，才能宣布第6项验收完成。

## 样本构成

- 公众用户2人：验证科普内容是否容易找到和理解。
- 中学生或一线教师2人：验证课堂使用和概念解释。
- 历史、古文字相关学生1人：验证记录与争议查阅。
- 古文字或历史教师/研究者1人：验证释文、著录、断代边界。
- 天文学教师/研究者1人：验证科学原理与天文对应表达。
- 项目指导教师或内容编辑1人：验证审核、作品与发布流程。

若只能完成5人，至少保留公众、学生/教师、古文字、天文学、内容审核五种视角。

## 测试准备

1. 记录当前发布版本编号和测试日期。
2. 公众任务直接使用当前公众站；研究任务使用测试草稿，不撤销现有发布内容，不删除资料。
3. 每位参与者先阅读测试说明并确认同意记录操作表现，不记录无关个人信息。
4. 主持人只读任务，不提示按钮位置；参与者明确求助后才提供帮助并记录一次求助。
5. 每位测试控制在30—45分钟，结束后立即填写问卷。

## 文件

- `测试任务.md`：主持人按用户类型分配的任务清单。
- `观察记录模板.md`：逐人记录路径、错误、语言反馈和严重问题。
- `测试后问卷.md`：10题SUS量表及开放问题。
- `汇总表.csv`：8个待招募席位和量化指标。
- `summarize_user_testing.py`：校验模板并在实际测试后生成汇总报告。

## 使用

先检查模板：

```powershell
python user-testing/summarize_user_testing.py --validate-only
```

完成至少5名真实参与者并在CSV中把状态改为`completed`后生成报告：

```powershell
python user-testing/summarize_user_testing.py
```

输出 `user-testing/用户测试汇总.md`。原始观察记录不应放入公众站或发布版本。

## 完成门槛

- 至少5名真实参与者完成；建议8名。
- 核心公众任务完成率不低于80%。
- 研究工作台关键任务没有阻断级问题。
- 平均SUS达到68分；未达到时必须列出改进项后复测。
- 严重级问题全部有负责人和处理结论。
- 古文字与天文学问题分别交由对应指导教师确认，不用普通可用性票数替代学术判断。
