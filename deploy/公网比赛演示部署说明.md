# 《甲骨里的日光缺口》公网比赛演示部署说明

## 1. 推荐结构

```text
访客浏览器
  -> HTTPS域名 / 安全隧道
  -> Caddy或cloudflared
  -> 127.0.0.1:8000
       |- /                 公众科普站
       |- /showcase/        参赛作品统一入口
       |- /research/        登录后的研究工作台
       |- /api/research/*   登录后的研究接口
       |- 私有PDF/SQLite    不提供静态访问
```

应用必须继续监听`127.0.0.1`。不要在路由器、安全组或Windows防火墙中直接开放8000端口。

参赛PPT中的二维码应统一指向`https://正式域名/showcase/`，不要直接指向首页的某个锚点。参赛入口会集中提供公众站、1080P演示视频、在线技术报告、参赛文件和源码仓库链接。

## 2. 正式比赛推荐：阿里云 ECS + 标准 Nginx

正式比赛站点计划迁移至阿里云 ECS。独立部署包、Ubuntu安装脚本、最小安全组、ICP备案判断、域名切换、HTTPS、数据迁移和回滚步骤见`deploy/aliyun/阿里云ECS部署与迁移说明.md`。若域名已备案，优先使用中国大陆地域；未备案时使用阿里云香港地域。

阿里云部署默认使用`/opt/oracle-eclipse/app`、独立低权限账号`oracle-eclipse`和本机端口`127.0.0.1:8018`。安全组只开放80、443以及限定管理员来源IP的22，不安装宝塔，也不直接公开应用端口。

## 3. 旧环境参考：韩国 Ubuntu + 宝塔 Nginx

以下内容只用于维护当前韩国服务器或紧急回退，不再作为新服务器的首选方案。

以下命令默认项目目录为`/www/wwwroot/oracle-eclipse-mvp`，宝塔运行用户为`www`。如果服务器实际目录或用户不同，必须同步修改 systemd 模板。

1. 在宝塔中新建 Python 项目或空站点，将域名 A 记录指向服务器公网 IP。先不要开放应用的 8000 端口。
2. 上传项目代码及当前运行数据。私有运行数据至少包括：

```text
source-materials/research.db
source-materials/pdfs/
source-materials/imports/
source-materials/generated/
source-materials/site-assets/
data/published-snapshot.json
data/release-history/
```

3. 在服务器安装 Python 3.11+、字体和 PDF 运行依赖，再创建虚拟环境：

```bash
cd /www/wwwroot/oracle-eclipse-mvp
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r deploy/ubuntu/requirements-server.txt
sudo chown -R www:www source-materials data
sudo chmod -R u=rwX,g=,o= source-materials
sudo chmod -R u=rwX,g=rX,o=rX data
```

4. 建立只在服务器保存的密钥文件：

```bash
sudo install -d -m 700 /etc/oracle-eclipse
sudo cp deploy/ubuntu/oracle-eclipse.env.example /etc/oracle-eclipse/oracle-eclipse.env
sudo chmod 600 /etc/oracle-eclipse/oracle-eclipse.env
sudo nano /etc/oracle-eclipse/oracle-eclipse.env
```

必须替换`DASHSCOPE_API_KEY`、研究工作台账号密码、`ORACLE_PUBLIC_CORS_ORIGIN`。密码或 Key 不得写入宝塔网站目录、Git、PPT或聊天记录。

也可在宝塔终端通过隐藏输入完成配置并重启服务：

```bash
sudo bash deploy/ubuntu/configure-secrets.sh sci.ljcode.cn
```

5. 安装并启动 systemd 服务：

```bash
sudo cp deploy/ubuntu/oracle-eclipse.service.example /etc/systemd/system/oracle-eclipse.service
sudo systemctl daemon-reload
sudo systemctl enable --now oracle-eclipse
sudo systemctl status oracle-eclipse --no-pager
curl --fail http://127.0.0.1:8000/api/health
```

6. 将`deploy/ubuntu/baota-nginx.conf.example`中的域名替换为正式域名，再合并到宝塔生成的网站配置。不要覆盖宝塔自动生成的 SSL 证书路径。随后在宝塔申请 Let's Encrypt 证书、启用强制 HTTPS，并重载 Nginx。

7. 公网依次验收：

```text
https://正式域名/                              公众科普站
https://正式域名/showcase/                     参赛作品统一入口
https://正式域名/showcase/technical-report.html 在线技术报告
https://正式域名/research/                     研究工作台登录页
```

默认线上环境支持网页展示、问答、OCR、语音、图片和结构化作品生成。增强 PPTX 下载还依赖 Node.js 及演示文稿导出模块；未配置前不影响在线幻灯片播放，但下载 PPTX 会提示缺少导出环境。

## 4. 备选：域名 + Caddy

适合有固定公网服务器和域名的比赛演示。Caddy自动申请和续期HTTPS证书。

1. 将域名A/AAAA记录指向服务器公网地址。
2. 安装Python、LibreOffice、Caddy及项目所需Python包。
3. 将项目放在仅服务账号可写的目录，确认`source-materials/`和`data/`具有持久化空间。
4. 在服务账号环境中配置：

```powershell
powershell -ExecutionPolicy Bypass -File tools/configure_bailian.ps1
powershell -ExecutionPolicy Bypass -File tools/configure_research_login.ps1
```

5. 启动比赛演示后端：

```powershell
powershell -ExecutionPolicy Bypass -File tools/start_public_demo.ps1 -Port 8000 -PublicOrigin "https://demo.example.com"
```

如需让评委在登录页直接进入演示工作台，启动前设置一次环境变量：

```powershell
$env:ORACLE_QUICK_LOGIN_ENABLED = "1"
```

快捷入口默认关闭。只有公开演示模式和已配置研究账号同时满足时才会显示；它创建的仍是服务端HttpOnly会话，不暴露账号密码。演示结束后改回`0`并重启服务。

启动后依次检查：

```text
https://demo.example.com/                         公众科普站
https://demo.example.com/showcase/                参赛作品入口
https://demo.example.com/showcase/technical-report.html  技术报告摘要
https://demo.example.com/research/                研究工作台登录页
```

6. 复制`deploy/Caddyfile.example`为服务器Caddyfile，并设置：

```powershell
$env:DEMO_DOMAIN = "demo.example.com"
caddy run --config deploy/Caddyfile.example
```

7. 使用系统服务管理Caddy和Python进程，配置异常退出后自动重启。不要把密码或API Key写进Caddyfile、仓库或日志。

## 5. 最终链接和二维码

正式提交前填写：

`deliverables/competition-2026/参赛链接配置.json`

```json
{
  "publicOrigin": "https://demo.example.com",
  "sourceUrl": "https://github.com/组织名/仓库名",
  "videoUrl": "https://可直接打开的1080P视频地址",
  "deckUrl": "https://demo.example.com/deliverables/competition-2026/甲骨里的日光缺口_参赛演示_赛道三方向2.pdf"
}
```

参赛入口与PPT构建读取同一个配置文件，不需要在网页中重复填写。更新后重新执行参赛PPT构建与PDF转换。最终版第14页必须显示三个真实二维码，不能保留“待配置”。

视频地址应满足：浏览器可直接点击、画面16:9、不低于1920×1080；如果使用夸克网盘，应确认评委在未登录状态下仍能打开分享页。

## 6. 公网验收

- 使用手机流量扫描二维码，确认不是只能在校园网或本机访问。
- 公众站、参赛入口、技术报告和视频不要求登录。
- 研究工作台必须登录，连续输错密码会触发限流。
- 原始PDF、SQLite、密钥、未确认资料和草稿访问均返回403或404。
- 公众问答在百炼暂时不可用时给出明确错误，不展示密钥或服务器路径。
- 首页Three.js场景在桌面和手机均不空白，交互控制不遮挡正文。
- PPT/PDF中的URL与二维码指向同一正式域名，不使用`127.0.0.1`或临时隧道地址。

## 7. 临时彩排：Cloudflare Tunnel

适合短时评审和彩排，不需要开放入站端口：

```powershell
powershell -ExecutionPolicy Bypass -File tools/start_public_demo.ps1
cloudflared tunnel --url http://127.0.0.1:8000
```

临时URL变化、依赖本机持续联网，并且电脑休眠后站点会中断。因此正式比赛更适合固定域名和持续运行的服务器。

## 8. 上线前数据准备

- 备份`source-materials/research.db`、`data/published-snapshot.json`、`data/release-history/`。
- 备份`source-materials/generated/`和当前发布版本引用的媒体文件。
- 确认7篇原始PDF仍在私有目录，网页无法直接访问。
- 为演示单独设置高强度研究账号密码，不与个人账号复用。
- 当前研究账号具有编辑、删除、审核和发布权限，只交给项目演示人员；不要把账号密码写进PPT、二维码或公开页面。若需要让评委自行登录，应先增加只读访客角色。
- 百炼API Key只配置在服务账号环境变量中，并设置合理额度告警。
- 默认公众问答限流为每IP每分钟30次；登录默认每IP五分钟10次。

## 9. 上线验收

```text
GET  /api/health                              -> 200
GET  /                                       -> 公众站可用
GET  /research/                              -> 未登录跳转登录页
POST /api/research/login                     -> 正确账号成功，Cookie含HttpOnly/SameSite/Secure
GET  /source-materials/research.db            -> 403
GET  /source-materials/pdfs/任意文件.pdf       -> 403
GET  /data/published-snapshot.json            -> 200
GET  /data/release-history/任意文件.json       -> 403
```

还需在桌面和手机网络各完成一次：公众问答、研究台登录、PDF页码联动、资料问答、作品批准、发布新版本和公众端刷新。

## 10. 比赛期间运行策略

- 提前一天完成部署并进行至少2小时连续运行测试。
- 评审前冻结数据库和当前发布版本备份，仅保留必要演示修改。
- 准备本地录屏作为网络故障时的降级方案。
- 开启服务日志，但不要记录请求Cookie、密码、API Key和论文全文。
- 比赛结束后立即关闭研究工作台公网入口或更换研究账号密码。

## 11. 回滚

应用更新失败时，恢复上一版代码、`research.db`和`published-snapshot.json`，再重启后端。公众发布版本本身可在研究工作台中恢复；数据库文件级恢复前必须先停止Python服务，避免覆盖正在写入的SQLite文件。
